1. Introduction

1.1 Overview

The Smart Agricultural Management System is a web-based agrarian IoT platform that lets agriculturalists, commercial farmers, and regional administrators monitor real-time soil telemetry, automate precision micro-drip irrigation, inspect reservoir capacities, and manage regional crop health from one central place. Soil moisture, chemical reaction (pH), primary macronutrients (Nitrogen, Phosphorus, Potassium), and temperature must be accurate, robust, and accessible across online and offline field settings, so the system uses role-based access for three primary users: platform administrators, registered farmers, and public agricultural customers.

The system follows a decoupled client-server architecture: a responsive single-page application built with modern vanilla ES6+ JavaScript and styled with an Obsidian Dark aesthetic talks to a Node.js and Express REST API, and all persistent operational data is stored in a structured JSON database. The report documents the project using OOASE practices: requirements prepared in MS Word, UML models, implementation in VS Code, Node.js and Express backend, API testing with Postman, and project and issue tracking in Jira.

1.2 Problem Statement

Many Tamil Nadu farmers still manage irrigation, fertilizer applications, and soil diagnostics through manual inspection and uncoordinated schedules, which causes recurring problems:

  • Scattered soil data – moisture, pH, and nutrient records are scattered across paper lab notes and quickly become outdated.
  • Manual irrigation control – pump sets and field valves are operated manually on-site, leading to irregular watering and wasted electricity.
  • Over-irrigation and water stress – crops receive either excess water causing root hypoxia or deficient water during sensitive reproductive phases because soil moisture is not measured in real time.
  • Delayed nutrient diagnostics – chemical soil lab reports take weeks to arrive, missing the window for corrective top-dressing fertilization.
  • Unmonitored reservoir levels – regional farmers lack visibility into state dam storage capacities (Mettur, Bhavani, Vaigai) during critical cropping seasons.
  • Poor reporting – irrigation histories, electricity consumption, and crop advisory logs are compiled by hand when needed.

1.3 Objectives

  • Maintain farmland telemetry, soil diagnostics, irrigation logs, and crop guidelines in one place.
  • Let farmers view live volumetric soil moisture, pH, NPK levels, and soil temperature with automatic fluctuation tracking.
  • Let farmers remotely toggle micro-drip solenoid valves with instant reactive feedback and automated moisture accumulation.
  • Let administrators calibrate sensor node fleets across 38 Tamil Nadu districts, audit system uptime, and monitor revenue analytics.
  • Guarantee multi-protocol operational resilience with dual-mode operation for both online networked servers and offline file environments.
  • Secure the system with login, role-based access, and model it with standard UML diagrams.

1.4 Scope of the Project

The system covers the complete agricultural monitoring cycle: the farmer registers an account and selects farmlands, the IoT node grid reports soil moisture and telemetry, the automated system triggers micro-drip solenoid valves when water stress occurs, the farmer inspects real-time crop health advisories, and the administrator reviews platform telemetry and system performance.

  • Included: user registration and authentication, role management (Farmer, Admin, Customer), live telemetry dashboard (Moisture, pH, NPK, Temperature), solenoid valve actuation toggle, dam storage radar gauges (Mettur, Bhavanisagar, Vaigai, Aliyar), customer directory, farmer testimonials, creator admin nexus, and offline localStorage fallback.
  • Not included: physical hardware sensor fabrication (simulated 12-second random-walk IoT telemetry stream implemented), satellite radar imagery processing, and native mobile compilation (responsive web client provided; see Section 6.3).

2.7 Business Rules

  • Creator Exclusivity: The Creator Admin Command Nexus is strictly reserved for Sanofar Fathima I. All non-admin attempts to access the portal are rejected with an administrative block modal.
  • Mandatory Terms Acceptance: A new farmer account can only be registered if the terms and conditions checkbox is explicitly acknowledged.
  • Actuation Sensory Feedback: When a micro-drip valve is toggled to ACTIVE, the system immediately applies a +1.2% moisture increase and updates the last irrigated timestamp.
  • Automated Solenoid Flow Rate: Active micro-drip irrigation dispenses precision water at an engineered baseline of 45 Liters per hour.
  • Critical Moisture Threshold: Soil moisture below 40% triggers a water stress alert; automatic irrigation shuts off when moisture reaches or exceeds 85% (field capacity).
  • Continuous Telemetry Fluctuation: The background simulation engine executes every 12 seconds, adjusting moisture and temperature within realistic diurnal bounds.
  • Sensor Recalibration Override: Administrative calibration sets all district moisture sensors to optimal ranges (60-70%) and resets health scores to 95+.
  • Dual-Mode Data Integrity: When operating offline, client mutations persist to localStorage and sync back when the REST server becomes available.
  • Single Identity Retention: Reserved system usernames cannot be registered or duplicated by public sign-up forms.

4. Project Coding

4.1 Architecture Overview

The system is a decoupled three-tier application. The presentation tier is a responsive Single Page Application built with vanilla ES6+ JavaScript and modern CSS; the application tier is a Node.js and Express REST API that validates requests and executes business rules; the data tier is a structured JSON store accessed with synchronous file system helpers. Client and server are organized in one repository and communicate through JSON over HTTP.

A request flows as follows: the page calls the API through the shared api.js module; Express applies CORS and body-parsing middleware and routes the request to the matching endpoint; the handler updates the in-memory state and persists changes to db.json; and the JSON result is rendered reactively by app.js.

6. Conclusion and References

6.1 Conclusion

The Smart Agricultural Management System shows how object-oriented analysis and modern web technology can organize precision agricultural telemetry and automated irrigation. The requirement analysis identified the user roles and a set of functional and non-functional requirements; the UML diagrams translated them into a clear design (use case for functions, class for data, sequence, activity and state chart for behaviour, component and deployment for architecture); and the design was implemented as a vanilla ES6+ front end, a Node.js and Express REST API, and a structured JSON data store.

The finished system lets farmers inspect real-time soil moisture, pH, and NPK metrics, actuate micro-drip solenoid valves with instant fluid feedback, review dam storage radar, and consult AI agronomic advisories; it provides administrators with fleet recalibration controls and commercial revenue analytics. Security rests on role-based access checkpoints and strict isolation of the Creator Admin Nexus; operational resilience is guaranteed by the dual-mode proxy pattern; the API was verified with a Postman collection and automated tests, and the work was planned in Jira. The project also gave practical experience of the complete software engineering cycle.

6.2 Limitations

  • Sensor feeds are simulated via server-side random-walk algorithms; no physical LoRaWAN/MQTT gateway hardware is physically connected.
  • Flat-file database (db.json) is optimized for academic demonstration and low-to-medium concurrency; high-throughput enterprise deployments require PostgreSQL/PostGIS.
  • The interface is a responsive web application; there is no native compiled Android or iOS mobile application.
  • Alerts are presented within the application dashboard only; direct GSM SMS and voice telephony dispatch are not integrated.

6.3 Future Enhancements

  • Integration with physical ESP32 microcontrollers and LoRaWAN gateways in Tamil Nadu farmlands via MQTT brokers.
  • Sentinel-2 satellite multispectral NDVI overlay integration to detect crop canopy vigor and drought stress from orbit.
  • Edge AI plant pathology diagnostic scanner using TensorFlow.js to detect fungal blights and pest infestations from leaf photos.
  • Progressive Web App (PWA) offline service worker packaging with automated regional SMS and voice alerts in Tamil.
  • Integration with UPI and RuPay banking gateways for agricultural cooperative subsidy disbursements.
